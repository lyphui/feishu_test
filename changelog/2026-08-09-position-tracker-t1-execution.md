# [已发布] — 2026-08-09（`PositionTracker` 统一 T+1 执行）

修掉前一条条目（[卖出端下单窗口](2026-08-09-sell-side-execution-window.md)）末尾
「已知问题」里记的执行时点问题。这次连带发现问题比原先描述的更大。

## 问题：一次回测里并存三套执行口径

| 分支 | 旧成交时点 |
|---|---|
| 建仓（`lookback` 窗口内，有 `intraday_map`） | **T+1**，分时价 |
| 建仓（窗口外的历史信号） | **T 日收盘** |
| 加仓 / 初仓阶段退出 | **T 日收盘** |
| 一级减仓「红柱缩短」（窗口内 / 窗口外） | **T+1** / **T 日收盘** |
| 二级「死叉」/ 三级「DIF<0」 | **T 日收盘** |

两个毛病：

1. **零延迟假设。**日线的 `signal` / `hist_shrinking` / `dif < dea` / `dif < 0`
   全都要等当日收盘才算得出来，而代码就在同一刻按那个收盘价成交。
2. **分界线是 `--lookback`。**这个参数本该只决定"打印哪几个信号的分时图"，
   却决定了历史区间用哪套成交规则——把它从 5 改成 500，历史收益会跟着变。

## 改法：全部排到下一个交易日

- 新增 `PositionTracker._place()` / `_execute()`，所有分支统一走它们，
  删掉全部 `self._sell_xxx(date, price, ...)` 式的当日直接成交。
- 每个遍历日最多排一条操作，且执行日恒为 T+1，因此 `_pending` 的 key 不会冲突，
  不需要优先级仲裁。待定操作在循环体**最开头**执行，状态先更新再判断当天，
  所以同一个条件不会被重复排单。
- 成交价优先级：① `intraday_map` 的分时价（`_executable_price()`）
  → ② **执行日**的日线收盘价。`intraday_map` 现在**只换价、不换日**。
- 信号落在最后一根 K 线 → 没有 T+1，该操作作废，仓位交给期末清算。
- 保留 `--exec_day same` 的当日成交：那是使用者明确选的盘中实时口径。
- 顺手删掉 `_overridden_sig_dates`：`date in intraday_map` 为假时
  `date not in _overridden_sig_dates` 恒为真，是条死逻辑。

## 行为变更

**是。** 交易日期、成交价、笔数、收益全都会变，历史结论必须重跑。

实测（40 只 A 股候选，同一批日线信号，`intraday_map={}` 即历史区间口径）：

| 指标 | 旧（当日收盘） | 新（T+1） |
|---|---|---|
| 平均收益 | +0.68% | **−1.29%** |
| 中位收益 | −0.02% | −0.02% |
| 交易笔数 | 251 | 231 |

- **差额平均 −1.97pp，中位 0.00pp；变好 15 只 / 变差 15 只 / 无交易 10 只。**
- 逐股看几乎是对称的，**均值全靠左尾**：跌得最狠的是 002281 光迅科技
  （+97.09% → +43.47%，−53.62pp）、002400 省广集团（−21.44pp）、
  002181 粤传媒（−20.32pp）——全是走势最陡的动量票。
- 这正是零延迟假设最占便宜的地方：动量票在信号形成的那根收盘价离场，
  等于精准卖在阶段顶；顺延一天就要把隔夜那段还回去。
  **旧口径不是"稍微乐观"，而是在最关键的少数票上系统性高估。**
- 笔数减少来自两处：信号落在最后一根 K 线时作废，以及顺延后状态先变、
  原本会连续触发的下一级条件被上一级的清仓抢先。
