# [已发布] — 2026-08-10（候选池纳入「买入」＋看空对照组＋两个 alpha 分开报）

回答两个此前报表答不了的问题：**这套评级有没有区分度**、**赚的是选股的钱
还是择时的钱**。

## 1. 候选池：收「买入 + 增持」，不再只收「增持」

`load_candidates` 旧实现硬编码 `rating != "增持"` 就跳过。当前数据里有
**51 只 A 股是「买入」**（Strong Buy）、239 只是「增持」——用中间档定义股票池、
把最强的那档整个丢在回测之外，没有理由。

```python
LONG_RATINGS    = ("买入", "增持")
CONTROL_RATINGS = ("减持", "卖出", "回避")

load_candidates(json_path, ratings=LONG_RATINGS)   # 默认
```

候选 dict 新增 `rating` 字段。去重规则不变：保留**首次落入所选评级集合**的
最早记录。实际池子从 239 只变为 **248 只**（增持 224 + 买入 24）。

`--ratings` 同时加到 `jcy_macd_bull_batch.py` 与 `param_sweep.py`。

## 2. 看空对照组 `--control`

```bash
python backtest/jcy_macd_bull_batch.py --control 减持,回避
```

用**完全相同的策略、参数、成本、指数**把看空池（58 只）再跑一遍，输出到
`output/control/`，并在 `output/summary_rating_compare.csv` 与控制台给出同口径
对照表。

只跑看多池最多能说明"这批票在这段行情里涨没涨"——牛市随便挑一篮子都涨。
看空池明显更差，"买入/增持"这个标签才带信息。表里明确标注**这是描述性对比，
不是显著性检验**：两池样本量与推荐日分布都不同，且所有标的共享同一段行情。

## 3. 两个 alpha 分开报

`summary.csv` 新增列：

| 列 | 含义 | 回答的问题 |
|---|---|---|
| `指数收益%` | 指数在该股统计窗口内的涨跌 | — |
| `选股alpha%` | `基准收益% − 指数收益%` | **研报推荐本身**值不值钱 |
| `超额收益%`（旧有） | `策略收益% − 基准收益%` | **MACD 择时**加不加分 |

项目宣称目标是"验证推荐的实际收益"，问的是第一个；而引擎默认给的
`benchmark_return` 是第二个。只看超额收益，会把"推荐了一批好票、择时反而
拖后腿"读成策略失败。`result_to_row(candidate, result, index_df=...)` 传了
指数才算得出这两列，否则为空。

## 4. 在场比例

引擎的日权益记录新增 `shares`，`run_backtest` 返回 `exposure_pct` /
`avg_holding_days`，`summary.csv` 新增 `在场比例%` / `平均持仓天数`。

`shrink_exit=True` 的策略大部分时间空仓，空仓日既不赚也不亏，最大回撤和夏普
都被"没参与"美化过。缓存的两只票实测**在场比例只有 2.5% / 3.1%**——不给出
这个数，`−23.78%` 的回撤看着像"控制住了风险"，实际是根本没参与。汇总表与
`_print_summary` 都显式标注**回撤/夏普未按暴露度调整**。

## 5. `param_sweep` 改用日均超额选参

`METRICS` 主指标从 `超额中位数%` 换成 **`日均超额中位bp`**（`--metric` 默认值
同步）。`batch_report` 早就论证过总超额% 跨窗口不可比（各股统计窗口从几十到
几百个交易日不等），扫描却一直在用它选参数——选出来的是"哪组参数恰好被长窗口
标的占了多数"。总超额% 保留在 METRICS 里仅供对照。新增 `平均在场比例%`。
